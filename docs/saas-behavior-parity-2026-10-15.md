# SaaS 行为对齐与恢复策略

对应已批准规格：`superpowers/specs/2026-10-14-saas-behavior-parity.md`。Mac 修改仅源码和隔离测试，不代表已签名发布。

## 可配置策略

统一服务器启动时校验配置。无效配置直接报告配置名，不静默采用更宽松策略。

| 环境变量 | 默认值 | 行为 |
| --- | --- | --- |
| `FLEET_SESSION_LIFETIME` | `720h` | 正式登录有效时长，Go duration，至少一分钟 |
| `FLEET_SESSION_SLIDING` | `true` | 正常已认证请求在剩余有效期不足一半时续期；可设 `false` 使用绝对有效期 |
| `FLEET_AUTH_WINDOW` | `15m` | 验证尝试统计窗口 |
| `FLEET_AUTH_ATTEMPTS` | `8` | 同一来源与账号/操作的尝试阈值 |
| `FLEET_AUTH_CONCURRENCY` | `4` | 同时执行密码验证的计算并发 |
| `FLEET_TRUSTED_PROXIES` | loopback CIDR | 逗号分隔 CIDR；显式空值不信任任何代理；只信任部署实际反向代理 |
| `FLEET_DEVICE_OUTAGE_GRACE_SECONDS` | `120` | 最后成功租约后的临时故障宽限，0–600 秒；0 禁用；明确撤权始终立即生效 |

设备状态保留旧 `lease_until`，新客户端优先使用 `lease_seconds` 和有界 `outage_grace_seconds`，以本机单调时间计时。旧客户端保持旧租约行为，必须更新 Mac 才获得时钟容错和故障宽限。

`autoCloseMinutes=0` 表示永不自动回收。空闲回收不能以断开浏览器连接为依据杀掉仍在运行的 tmux 命令。窗口和缓存配置为资源管理目标，带草稿、活动任务或等待批准的会话不因缓存回收丢失内容。

## 文件与迁移

文件默认打开用户主目录，但可访问系统实际允许的其他路径。登录、设备归属校验及系统权限继续生效；上传不覆盖已有文件。文本预览最多 5 MiB，超过显示“文件过大，不支持预览”并提供下载；下载保留原始字节。编码自动识别存在歧义时可手动选择。

原生迁移保留旧持久消息队列作为唯一投递记录，不复制第二份可重复投递的队列。若旧版和原生版各自有不同的未完成队列，先保留两份原始文件并显示具体路径和处理方式，不静默合并或删除。升级只维护 Fleet 后台时，不重启 Codex shared keeper/app-server，也不终止 tmux 命令。

## 验证范围

每个业务负责人先记录失败行为测试再修复，主任务执行项目 `scripts/verify.sh`。新增覆盖认证恢复/轮换竞态、租约时差/撤权/宽限、组件恢复和监听进程归属、队列与配置迁移、文件大小边界和下载、DSH 模型选择、新会话项目选择及离线显式发送。测试通过不等于已完成正式 Mac 签名、升级 rollout 或用户真实浏览器验收。
