# 设置交互统一整改

用户已确认本批需求：先完成 build 3，再将下面问题全部修好，统一打包到 abj 独立验收实例。不更新本机现有应用、launchd、Desktop 或其他生产节点。

## 原生客户端

- 运行状态直接设置登录后自动启动；关联账号只包含服务器地址、网页授权和解绑。
- 判断规范化后的真实应用位置，只有 `/Applications/Fleet Hub.app` 可以运行后台。DMG、Downloads、临时开发应用不能绕过此边界。非安装位置提供安装或打开已安装应用的入口，不能永久灰掉授权操作；保留已有应用，不静默覆盖。
- 裸域名或 IP:port 自动补 HTTPS；拒绝 HTTP、路径、凭据、查询和片段。服务器地址停止输入 600ms 后自动保存，授权按钮同步保存最新草稿后每次发起新的 OAuth。保存中可继续输入，旧响应不得覆盖新草稿，写入串行；失败显示实际错误且可重试。
- 自动启动与服务器设置分别可操作，未关联时允许空服务器地址保存自动启动设置，但空地址不能授权。SMAppService 失败应回滚后台设置，不显示成功。
- 临时目录打开的应用点击网页授权先进入安装/打开已安装应用，传递经验证的服务器地址并在安装位置明确继续授权。不把密码、TOTP 或 token 放入启动参数。
- FDA 检查、独立 Agent 身份、更新空闲守卫与回滚保持不变。

## Web 统一设置弹窗

- 一个对话框、四个独立内容页：账号、添加设备、自动化、会话设置。菜单各入口打开相应页，弹窗内部也可切页。桌面侧栏、移动横向菜单；内容独立滚动，关闭与键盘焦点一致。
- 复用 account.js 原账号安全 API 和现有自动化/会话控件，不用 iframe，不复制鉴权。账号页保留个人设备、登录会话、密码、验证器、恢复码和退出功能；下载说明仅在添加设备页。
- 切页、关闭时确认丢弃未提交表单；验证器更换和恢复码保存步骤禁止静默离开。异步加载使用版本序号，过期结果不得覆盖当前页。私有状态只存 DOM，退出时清理。
- `/account` 保持可直接访问，`/account#add-device` 兼容独立添加设备页。权限与 CSRF 不变。
- 归档、轻量主题选择继续留在原菜单；管理员与退出入口保留。

## 视觉和登录

- 沿用 Titanium 表面、字体、圆角和无常驻边框规范；输入使用独立表面色，确保明暗模式可辨识。主题选择改紧凑文字/图标，不用分段容器。
- 登录与注册互相链接并保留 next；验证码设置、验证、恢复码确认中不显示离开流程的切换。
- 原生 CSS/SVG 细网格和单个光标探针，不引入动画依赖、不读取表单、不上传鼠标数据。参考浏览器 Pointer Events、requestAnimationFrame、prefers-reduced-motion 的能力边界；只在精细指针且允许动效时跟随，触屏和减少动画为静态。

## 验证与发布

动效调研依据：[MDN pointermove](https://developer.mozilla.org/en-US/docs/Web/API/Element/pointermove_event)、[MDN 减少动态效果](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion)。实现只更新探针 transform，每帧最多一次；页面隐藏、粗指针或偏好变化时取消追踪。

每个行为先失败测试、再实现；Swift、Go、JS 回归加独立浏览器验证。最终 `bash scripts/verify.sh` 完整通过后聚焦提交。下一不可变 build 大于 3，唯一签名机发行入口签名、公证、更新 abj、真实下载验签；不以单元测试代替 TCC、账号注册或真实入网人工验收。
