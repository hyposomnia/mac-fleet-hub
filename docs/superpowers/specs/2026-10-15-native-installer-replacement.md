# 原生安装完整替换与安装盘图标

用户要求：Applications 图标必须正常显示；发现旧版先明确确认卸载并安装新版，确认后完整替换，不要求用户手工清理。

## 行为与验收

- DMG 的 Applications 入口使用附带系统 Applications 图标的 Finder 替身，目标仍为 `/Applications`；只读挂载后图标可见且目标可解析，不修改系统文件夹图标。
- 检测已安装的设置应用或旧命令行后台时，展示明确替换确认。取消不变更文件或服务。
- 确认后备份并移除旧程序/启动项，安装新版；成功后只运行新版 Fleet 后台，失败自动回滚。
- 原生升级保留账号关联、配置、持久消息队列与会话记录。旧 CLI 迁移保留原始关联记录及配置，但原生网络身份不同，需网页重新确认关联；在同一次替换确认中说明。完整替换程序不等于清除用户数据。
- Desktop-owned Codex turn 不阻止仅 Fleet 替换，不终止 shared listener 或用户 tmux 任务；真实 Fleet-owned turn 和投递中的消息仍保护并给出可理解的等待说明。
- 界面不显示原始 `active_or_unknown`、会话 UUID 和日志 marker。
- 回归覆盖取消/确认、应用包替换/失败回滚、旧 CLI 清理、Desktop 与 Fleet 会话归属、图标内嵌与 Finder 只读挂载效果。
- 修复后通过项目验证入口，递增构建号，使用正式完整签名/公证发布流程；保留旧分发版本以便回滚。

## 旧 CLI 兼容边界

旧 CLI 没有原生版的维护控制接口，也没有 SIGTERM 排空机制，无法在不先更新旧进程的情况下原子冻结接单。迁移检查实时 Fleet 归属、消息投递状态和 DeepSeek 活动；Claude 的独立 tmux 与 Codex shared 服务保留。确认提示说明替换期间旧网页短暂断开、避免新发任务；检查与停机之间仍有旧协议固有的狭窄竞态，不能宣称已提供原子排空保证。原生升级继续使用现有维护控制接口。
