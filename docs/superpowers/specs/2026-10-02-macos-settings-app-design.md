# Fleet Hub macOS 设置应用与图形化发行设计

状态：用户于 2026-10-03 确认设计并授权开始，追加完全磁盘访问引导与验证。在 codex/multi-user-server 继续 SDD + TDD 实现；本文不是已实现、签名或部署证据。

## 1. 产品目标

对普通用户只交付真正的 macOS 应用，不再把源码压缩包当作安装包。Fleet Hub 是管理本机 fleet-agent 的设置应用，窗口退出不影响已经安装的后台服务；网页继续承担账户注册、登录、Authenticator 和远程设备操作。

范围包含设置应用、后台管理接口、安装/卸载、全应用更新、安全发行、abj 验收下载源，以及对应的 Web 安装说明。沿用用户/设备/管理员与现有逐设备授权协议，不增加租户或部署模式概念。

不替换旧生产网关或其他 Mac，不终止 Desktop 的活动 turn，不把开发构建当成正式下载包。新的客户端继续在唯一构建机签名和 Apple 公证。

## 2. 交付形式与选型

推荐：原生 SwiftUI/AppKit 设置应用、现有 Go agent 后台服务、DMG 分发。

- DMG 中只展示 Fleet Hub.app、Applications 快捷方式和简短安装引导；用户把应用拖入应用程序，或者双击应用中的“安装到应用程序”入口。
- 从只读 DMG 或下载目录运行时，先完成安装位置检查。复制成功后打开 Applications 中的正式应用，不能从临时挂载位置登记常驻服务。
- 首次后台组件安装在应用内完成；需要提升权限时使用 macOS 的系统授权界面，不打开 Terminal，不让用户填写命令或把密码交给应用。
- 支持 macOS 13 及以上，Intel 与 Apple Silicon。优先提供同一个 universal 应用；内部工具可按架构选择，网页不要求用户识别 CPU 架构。
- 原生应用比 Electron 更轻，适合少量系统设置；WebView 包壳不解决服务生命周期、权限和安全升级，故不采用。
- 用户可见发行物为 Fleet-Hub.dmg。升级使用只含完整签名应用的 Fleet-Hub-update.zip；这不是源码包，也不在 Web 面向用户的安装入口展示。

## 3. 应用界面

一个设置窗口，以状态、连接、后台、更新和高级五个区域组织；不做新的远程操作客户端，也不默认增加菜单栏常驻图标。

### 状态

- 状态区区分未配置、待授权、正在连接、运行正常、服务已停止、离线、授权已撤销和异常，不能只以进程存在显示“正常”。
- 显示设备名称、设备编号、关联账号、服务器、mesh 地址、后台 PID、应用版本、实际运行 agent 版本与最近检查时间。
- 常用操作为启动、停止、重启、打开控制台网页、重新检查。故障时展示可执行的下一步与脱敏诊断信息。
- 只打开应用不会自动安装、迁移网络或重启服务；关闭窗口或退出应用不停止后台服务。

### 连接

- 唯一连接参数为服务网页地址，支持合法 HTTPS 域名/IP 与端口，不要求输入 Headscale 地址、编号或手工 key。
- “保存并生效”先校验地址/TLS/服务能力，再原子保存；失败保留原配置与运行状态。
- 未关联设备时保存后进入“连接并授权”：由 agent 发起配对，自动打开系统浏览器，应用显示名称与短码。
- 浏览器完成登录、TOTP 与明确的账号关联确认；应用收到授权后显示账号、设备及服务器，用户在应用中点击“确认接入”，替代原终端 y。
- 应用内不输入、读取或记录网站密码、TOTP、恢复码、浏览器 Cookie。
- 已关联时修改服务器，明确提示需要解绑与重新授权。新服务器未验证成功前不退出旧网络；提交切换前确认撤销原关联。撤销失败保留锁定状态供重试，不能静默形成两个有效归属。
- 连接到其他控制面时单独明确告知网络切换影响。保留原 Tailscale profile 并记录回退信息，不 logout 销毁旧网络身份。
- 配对过期可在应用内重新发起；关闭设置窗口不等于确认配对，也不能自动接入未确认的账号。

### 后台

- “登录后自动运行”默认开启，并解释：Mac 重启且该用户登录后自动启动；不是声称未登录的系统用户也能运行其会话服务。
- 系统后台项目审批通过后才显示启用；被用户或系统禁用时显示实际状态，不能仅显示配置文件期望值。
- 自动运行开关与当前运行状态分开：关闭自动运行不等于立即停止本次运行；“停止服务”也不撤销设备归属。
- 保存服务设置后只重载必要的 Fleet 服务。健康的 shared Codex app-server 与 Desktop 环境保持原样，不能借安装或重启 agent 杀掉 Desktop 活动 turn。
- 浏览器终端与文件服务继续仅 loopback 监听，统一经带逐设备凭据的 agent 代理。

### 更新

- 显示已安装应用版本、运行 agent 版本、最新版本、发布说明及检查时间；提供“检查更新”和“下载并安装”。第一版不默认静默自动安装。
- 更新源始终由保存的服务 origin 派生，不回退 GitHub 或固定网关，也不允许任意独立更新 URL。
- 下载进度、校验、安装、重启、健康验证分别可见；更新替换的是整个 Fleet Hub.app 及其配套服务，不是只替换 agent。
- 更新前执行现有 Fleet-owned turn/消息投递安全守卫；繁忙时提示稍后，不中断活动操作。Desktop-owned turn 不因 agent 更新而被杀。
- 下载/验签失败不停止现有服务。安装失败恢复旧应用及必要的服务配置；保留一份可恢复旧版本。版本策略拒绝意外降级。
- 安装完成后重新打开新版本设置应用，确认新应用版本、后台新 PID、agent 磁盘版本与健康状态一致才显示更新成功。

### 高级与卸载

- 权限区域增加“完全磁盘访问”：展示实际后台进程的受保护文件访问检测、未授予/访问受限/待验证状态、打开 macOS 设置、定位实际授权对象、授权后重新检查与必要的服务重启。
- 完全磁盘访问不能由应用自动弹框授予，也不能使用 sudo 或修改 TCC 数据库冒充授权。用户必须在“系统设置 → 隐私与安全性 → 完全磁盘访问”中开启。
- 发布使用固定签名身份且独立安装/运行的 Fleet Agent.app 后台包。Hub 只负责设置，不承担磁盘权限；2026-10-07 目标机暴露了当前嵌套后台被归到 Hub 的架构缺陷，需要调整后台安装/启动而非要求用户授权主应用。最终以后台 TCC 权限主体及受保护目标访问验证，不仅凭开关或普通文件读取判断。
- 检测由真实后台进程执行固定受保护路径的只读打开探测，不读取文件内容、不枚举私人记录、不保存敏感路径/数据；不存在的探测目标或后台未运行时显示待验证，而非已授权。成功表示选定受保护目标已验证可访问，不夸大为所有 POSIX 权限都可绕过。
- 本机 POSIX/ACL 权限仍生效；撤销 FDA 后及时显示访问受限，UI 与 Web 提供相应排查说明，不能静默空列表冒充无文件。
- Web 的图形化安装步骤同步加入“在应用中检查完全磁盘访问，按引导开启并复检”。

- 提供脱敏诊断、日志位置与卸载入口；诊断不能包含配对领取令牌、设备/代理 token、TOTP 或用户会话正文。
- 卸载需要确认：先本地锁定远程访问，再尝试服务端撤销设备，停止 Fleet 自己的后台项目，恢复其明确管理的配置并移除应用/运行时。
- 无法访问服务器时明确显示“本机访问已关闭，服务端撤销未确认”，提供重试；不能伪报服务器设备已删除。
- 是否清理本地设置由用户选择；不删除 Claude/Codex 会话、用户文件、整个 Homebrew、既有独立安装的 Tailscale 或其他用户配置。
- 若由应用创建专属网络辅助组件，只清理由本应用安装清单证明归属的组件。网络回退和设备撤销是不同操作，分别给出结果。

## 4. 服务与权限架构

```text
Fleet Hub.app（设置 UI，可退出）
  ├─ 本地受限管理接口 → fleet-agent/用户后台协调器 → launchd
  ├─ 系统浏览器 → 现有账户认证与设备确认页面
  ├─ 系统授权 + 严格验证调用者的辅助组件 → 必需的网络/安装操作
  └─ 同源更新清单 → 签名应用升级事务
```

- UI 不充当 daemon，也不以 UI 进程的生命周期控制 agent。服务由 launchd 管理，使用独立稳定运行路径，不依赖应用窗口或挂载的 DMG。
- 复用 Go 现有配对、租约、归属、服务状态与安全守卫，新增机器可读的本地管理契约，不用解析中文 CLI 文本来驱动界面。
- 管理连接只采用同 UID 私有 Unix socket/受限 XPC，不新增 mesh 或公网 HTTP 管理端点；访问状态文件和令牌目录仍为 0700/0600。
- 后台读取同一份持久设置，禁止只改 UI 内存或 ~/.zshrc 然后宣称常驻配置生效。配置具有 schema、原子写入、版本迁移与失败恢复。
- 需要 root 的操作通过 macOS 系统授权和受限辅助组件完成；验证签名调用者、限定 UID、固定操作和路径，不提供任意 shell、任意文件写入或宽泛 sudo 通道。
- 首次交付包含固定版本的必需运行组件或通过校验的图形化依赖安装；不要求用户预装 Homebrew，也不把可执行下载交给未验证的 shell 管道。
- 对已有 Tailscale/共享 Codex 环境先检测，再复用或明确申请切换；不安装第二份冲突网络服务，不扩大本机监听范围。
- 第三方组件记录版本、来源、许可证与校验信息；实际打包和许可证检查必须通过，不能用运行时缺依赖的空壳 app 冒充可用安装器。

## 5. 服务器发行与更新契约

新的面向应用清单使用 `/enroll/client-release.json`，不静默改变当前旧 CLI release.json 的 schema。

清单包含 schema、应用 bundle identifier、版本、单调 build number、最低 macOS 版本、架构、发布日期、发布说明、签名更新包信息、DMG 下载路径与 SHA256/大小。版本值是正式发行版本，不以 git short SHA 作为唯一的产品版本。

- `/enroll/Fleet-Hub.dmg`：当前正式安装包。
- `/enroll/Fleet-Hub-update.zip`：当前完整签名应用升级包。
- `/enroll/client-release.json`：当前发布元信息；内含不可变、同源版本化资源路径，避免获取清单后发行源切换造成包不匹配。
- 实际 storage 使用不可变版本目录，并原子切换 current；仅允许列出的公共下载路径，不允许绕过 Go owner 授权访问私有设备路径。
- 服务器 origin/文件根目录由部署变量配置；客户端使用保存的 origin，Web 使用当前 location.origin。页面及客户端源码不写入 abj 实际 IP、端口或真实证书路径。
- 只在真正的 .app、DMG 和升级包完成签名、公证及发布后提供可点击下载；下载 404 时明确提示发行未就绪，不能回退源码包。
- 更新安全同时检查 TLS、同源下载及重定向策略、升级包签名、内嵌公钥、SHA/大小、固定 Developer ID Team/bundle 身份，以及 Apple 公证与版本政策。服务器提供的 SHA 本身不是发行者身份凭据。
- 推荐使用 Sparkle 2 的签名升级机制与原生安装事务，而不是自己从零实现应用覆盖器；其 feed 同样位于配置服务器下。正式实现需把动态 feed、签名校验及服务升级钩子集成测试，不能只做检查版本按钮。
- 更新清单与 feed 由唯一签名机生成，只向服务器发布公有产物与签名，不把私钥、公证密码放到 abj 或仓库。

## 6. Web 同步改造

账户页“添加设备”的首要按钮改为“下载 macOS 应用”；旁边展示应用版本、最低系统版本、包大小和简洁发布说明。

面向普通用户只展示以下步骤：

1. 下载并打开 DMG，将 Fleet Hub 拖入“应用程序”，或点击“安装到应用程序”。
2. 打开 Fleet Hub，填入本服务网页地址；网页提供“复制服务器地址”，地址来自当前 origin。
3. 点击“保存并连接”，浏览器自动打开；登录账户并确认关联。
4. 返回应用核对账号与设备，点击“确认接入”，按系统提示授权后台服务。
5. 状态显示“运行正常”后可以关闭应用；服务保持运行，网页可查看设备。

另提供“更新客户端”说明：打开应用 → 检查更新 → 从当前服务器下载 → 安装完成后确认状态。说明关闭窗口不停止服务、自动运行的登录后语义，以及故障/解绑/卸载入口。

取消源码 tar.gz、裸架构二进制、Homebrew、解压、bash、Terminal y 等作为推荐安装方式。旧 CLI 技术入口可保留兼容但不出现在普通用户的安装引导中；不能先切换网页推荐下载而后续才补真实 app 包。

## 7. 状态与失败契约

- 配置流程：草稿 → 校验 → 保存待连接 → 浏览器确认 → 应用明确确认 → 网络接入 → 节点校验 → 服务安装/健康检查 → 运行。
- 已运行配置修改：预检新值 → 明确授权相关副作用 → 事务提交 → 必要重载 → 健康验证；失败恢复原有效配置或显示明确锁定/待恢复状态。
- 更新流程：发现新版本 → 下载 → 发行签名/系统版本/身份验证 → 空闲守卫 → 备份 → 应用替换与服务切换 → 健康确认；失败恢复旧可运行版本。
- 所有长操作可见进度、明确超时与重试；禁用重复点击。取消不得被当作同意网络切换、解绑或升级。
- 进程加载、授权有效、网络节点登记和远程代理可用分别取证；一个条件通过不能伪造其余状态。

## 8. 实现与验收顺序

1. 先测试并实现机器可读的状态/配置/配对确认/自动运行管理契约，OS 操作使用隔离适配器，不直接更改当前 Desktop。
2. 再完成设置窗口与状态模型测试：初始化、校验失败、保存回滚、关闭窗口后台不停止、浏览器配对与应用确认、重启/停止/开关实际状态。
3. 完成依赖、系统授权、安装位置、后台登记和卸载归属清单；真实 macOS 验证系统权限提示，不用 mocked sudo 的结果冒充实机安装。
4. 集成全应用签名升级：非法 feed/错误签名/错误 Team/错误版本/繁忙守卫/中断下载/健康失败回滚先红后绿。
5. 扩展唯一候选发布入口：干净特性分支、完整验证、嵌套组件签名、应用公证 Accepted、staple、DMG 与 feed 发布、真实 HTTPS 下载与系统验签。
6. 真实 app 发行就绪后原子更新 abj 下载源与 Web 引导；保留原生产服务不变。在当前 Mac 实测 DMG 安装、浏览器授权、关窗口后台运行、登录后自动运行、应用升级、卸载与网络回退。

最终分别报告源码/自动测试、正式签名发行、abj HTTP/Web、Mac 实机和需要用户本人完成的系统/账号授权证据；任何未验证项明确列出，不再以源码压缩包代替产品交付。
